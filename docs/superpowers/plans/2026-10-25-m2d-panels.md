# M2d-panels: Playable Loop on Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After this plan the player can play the whole loop on screen with the owner alone:
- create a game in a concept wizard, develop it with sliders, and release it;
- read the four outlet reviews and watch sales and money;
- buy research and dev kits, build an engine, hire;
- make the next game.

Two mini-games come with it: production events and bug hunt.

**Publisher pitch (spec §11.5) is deferred, and no plan owns it.** `Contract.Kind.PUBLISHING`, the publisher revenue split in `SalesSystem` and three `AI_PUBLISHER` companies exist. No command creates a publishing contract, though, and M2b Ruling B6 says "M2 has no publisher-deal command". The pitch therefore has nothing to attach to. This is a gap against foundation §6.1 and M2 spec §11.5, flagged for the manager (Ruling P2).

**Architecture:**
- **Simulation side.**
  - Production events are content (`ProductionEventDef`). They are rolled by a new stateless `ProductionEventSystem`, called from the unclaimed `WorldEventSystem` stub (tick step 2), so `Simulation.SYSTEMS` is unchanged.
  - A rolled event is a `Decision` whose `kind` is the event id. `ChooseEventOptionCommand` applies the fixed effects.
  - Bug hunt is a UI-only timed game. Its result goes to `SubmitBugHuntCommand`, which is capped by tuning and allowed once per project.
- **UI side.**
  - Five code-built dock panels on a shared `PanelBase`.
  - Popup content classes, mounted in the existing `PopupCard`.
  - A `PopupQueue`: one popup at a time, pause on the first popup, resume after the last.
  - A `PopupDirector` that turns `EventBus` events into popups.
  - Everything reads through `StateQueries`, greys out buttons with the command's own `validate`, and submits through `GameRunner.submit()`.

**Tech Stack:** Godot 4.7.2, GDScript (static typing), GUT 9.x.

**Spec:**
- `docs/superpowers/specs/2026-10-24-m2-playable-garage-design.md`: §6 (loop), §9, §10, §11.3, §11.4, §11.5, §12.
- `docs/superpowers/specs/2026-10-25-ui-restyle-design.md` (direction C look; the PanelHost, PopupCard and Dock APIs).

Structure and conventions follow `docs/superpowers/plans/2026-10-25-m2d-restyle.md`; its Rulings 5, 9, 11, 13, 14 and 19 still hold. The ledger notes in `.superpowers/sdd/2026-10-25-m2d-restyle/progress.md` apply: popups pause through `GameRunner`, and nested popups resume only when the last one closes.

## Rulings made in this plan

| # | Ruling | Why / cost if wrong |
|---|---|---|
| P1 | **Sequencing.** This plan runs **now, before M2b and M2c**, on the M2a commands. Spec §2 says panels finish last; the user asked for a playable loop first. The M2b/M2c screens need a follow-up panels plan: skill tree, candidates, raises, equipment buy/lease/sell, office move, loans, contract work (M2b B18), marketing, promotions, patches, DLC, forum and awards. **Files shared with M2b/M2c:** `tuning_def.gd` and `tuning.tres` (field and value land in one commit), `fixtures.gd`, `state_validator.gd`, `content_db.gd`, `project.gd`, `strings.csv`, `state_queries.gd` (M2b T16 appends to it) and `game_session.gd` (M2b T11). Whichever plan merges second rebases onto these. | The user's goal. Cost: rebase conflicts in those files, all append-only. |
| P2 | **Publisher pitch deferred, no owner.** See the header. The spec gap is flagged for the manager, and M2b's Negotiator `publisher_share_bp` stays unused. | Building a deal flow here would invent M3-sized design. Cost: §11.5 is two-thirds done. |
| P3 | **Production events roll in tick step 2.** `WorldEventSystem.tick(ctx)` calls `ProductionEventSystem.tick(ctx)`, and nothing else changes in the stub. `Simulation.SYSTEMS` (spec §5's fixed list, which M2b and M2c rely on) and `production_system.gd` (M2b T4 owns it) stay untouched. Unit tests that call `ProductionSystem.tick` see no new draws. Rolls therefore see the phase from the end of last week. M3's world events add their own call next to it. | Cost: moving one call. |
| P4 | **An event is a `Decision` with `kind` = `ProductionEventDef.id`** (prefix `pevent_`), `related_ids = [project_id]`, `option_keys = def.option_keys` and `deadline_week = week + production_event_answer_weeks`. `Decision` gets no new field, and `missing_refs` checks `pevent_` kinds. | Cost: a later payload needs a Decision field then. |
| P5 | **Eligibility and draws.** Each tick, for each project in `state.sorted_ids(state.projects)`, the project is **eligible** only if all of these hold: (a) the player company owns it; (b) it is `kind == GAME` in `PRODUCTION`; (c) `GameRules.working_staff` is not empty; (d) `event_ids.size() < production_event_max_per_project`; (e) no pending `pevent_` decision has it in `related_ids`; (f) at least one event id in `GameState.sorted_names(content.production_events)` is not in `event_ids`. An eligible project draws exactly one `Fixed.roll_bp(ctx.rng, production_event_chance_bp)`. On a hit it draws one `ctx.rng.randi_range(0, n − 1)` over the sorted eligible ids. An ineligible project draws nothing. | Determinism: fixture content has no events, so every existing fixture test keeps its RNG stream. |
| P6 | **Expiry has no effect.** Before rolling, every pending decision whose `kind` is a production event and whose `deadline_week <= state.week` is removed through `Removal.remove_decision` (sorted by id), with no effects. | `test_m2a_playthrough` never answers. A default effect could push its fixed releases out of POLISH. In real play the popup is modal, so expiry only happens in headless runs. |
| P7 | **Effects are a closed set, applied in `ProductionEventDef.EFFECTS` order:** `design`, `tech`, `art`, `audio` (added to `points`, result clamped ≥ 0; a missing key whose result is 0 is not inserted; new keys go in sorted order, like `ProductionSystem._add_points`); `bugs` (clamped ≥ 0); `hype` (clamped 0–100); `morale` (added to every staff member with `assigned_project_id == project_id`, owner included, in sorted id order, clamped 0–100); `progress_bp` (only while the project is in PRODUCTION; `stage_progress` is clamped to 0..9999, so an event never completes or rewinds a stage). An answer is valid in any phase. The spec's "weeks" effect is `progress_bp`. | Cost: one function. |
| P8 | **Event content format.** `option_keys: Array[StringName]` holds 2–3 keys. `option_a`, `option_b` and `option_c` are each a `Dictionary[StringName, int]`, and an unused slot is `{}`. There is no default option. `ContentDB.validate` checks keys and limits (Task 1). | Typed dictionaries nested in an array do not round-trip through `.tres`. |
| P9 | **New Project fields:** `event_ids: Array[StringName]` (rolled events, in roll order; this stops repeats and caps the count) and `bug_hunt_done: bool`. | Cost: a schema bump if they are wrong later. |
| P10 | **Bug hunt.** At most once per project, in POLISH, for player GAME projects. Bugs removed = `mini(caught, mini(bug_hunt_max_bugs, bugs))`. The real-time game is UI-only: its length is `TuningDef.bug_hunt_seconds` (float, pacing). The spawn count (`cap + 4`) and the bug lifetime (1.6 s) are UI constants, because they are feel and the simulation never sees them. It is offered by a popup when a player GAME enters POLISH, and by a Project-panel button until release. Skipping sends nothing. | Without once-per-project, the cap means nothing. |
| P11 | **Auto-pause resume.** `GameSession.step_once` already sets `speed = 0` when a decision appears. It now also stores `auto_paused_speed` (the speed before the pause) and emits `speed_changed {speed: 0}`. `GameRunner.pause_for_popup` adopts `auto_paused_speed` when `speed` is already 0, so answering the event popup resumes the earlier speed. `GameSession.set_speed` clears `auto_paused_speed`. | Without it the game stays paused after every event, and the speed control shows a stale speed. Cost: a few lines in M2b T11's file. |
| P12 | **Popup queue.** One popup is visible at a time, in arrival order. `pause_for_popup()` is called when a popup shows and none was showing; `resume_after_popup()` is called when the last one closes. `game_loaded` clears the queue, then queues the pending production events of the loaded save. | Ledger note. |
| P13 | **Content in the UI.** `Main` passes `ContentDB.active()` to `PanelBase.configure(content)` and to `PopupDirector.setup`. `StateQueries` functions that need content take a `ContentDB` parameter. This extends restyle Rulings 5 and 13. | Keeps hard rule 3 and the fixture-content tests. |
| P14 | **Buttons.** A panel enables a button only when `cmd.validate(view, t).ok`, and sets its `tooltip_text` to `tr(reason_key)` otherwise. After `GameRunner.submit`, a failure is shown in the panel's `%Status` label as `tr(result.reason_key)`. | One pattern for every panel. |
| P15 | **Hiring** uses the existing `HireStaffCommand` with the name the player types (`LineEdit`; Hire is disabled while the stripped text is empty) and `TuningDef.hire_offer_salary`. A new game has equipment only at seat 0, so a hire has no computer and produces nothing until M2b equipment. The Team row shows a "No computer" chip, and the owner row shows a "Skill tree coming soon" placeholder chip. | M2b replaces hiring with candidates. |
| P16 | **Engine flow.** The Project panel has "New engine": a popup with a title and researched features, sending `StartProjectCommand.engine`. The real `lic_engine_homebrew` has no features, so without an engine flow researched features are a dead end. | Cost: one small popup. |
| P17 | **Wizard platforms** lists only platforms that are `ON_SALE` with a dev kit (what `StartProject` accepts). A hint appears when other on-sale platforms lack a kit. Built-engine choice ids are `StringName("built_%d" % engine_id)`; licensed engines use their content id. | `ChoiceRow` ids are StringNames. |
| P18 | **Slider rebalance** (UI only, ints): the changed slider takes `clampi(v, 0, 10000)`. The other two slots `i < j` share `rest = 10000 − v` in proportion to their old values. `vj = rest × old_j / (old_i + old_j)` (floor); `vi = rest − vj`, so `i` takes the remainder. When both are 0: `vi = rest − rest / 2`, `vj = rest / 2`. Slider step is 500. | Every stage always sums to 10000, which `SetSlidersCommand` requires. |
| P19 | **Review text** keys have `{genre}`/`{platform}` placeholders: the UI formats them with `tr(genre.name_key)` and `tr(platform.name_key)`. | `review.*` rows in `strings.csv`. |

## Review Focus

1. **Several popups in one event batch** (release while an event arrives, or two events in a row): one popup shows at a time, the game stays paused until the last one closes, and then it resumes at the earlier speed. Tests: Task 5 (`test_two_pushes_show_one_at_a_time`, `test_resume_only_after_last_close`), Task 14 (`test_review_and_event_in_one_batch_queue_in_order`).
2. **Loading a save while a popup is open, with an event pending in the save:** the old popups vanish, the pending event's popup shows, and nothing from the old session is submitted. Tests: Task 5 (`test_clear_frees_current_and_pending`), Task 14 (`test_game_loaded_requeues_pending_events`).
3. **Thai text in panels and popups:** no number is clipped, and nothing leaves its card or 640×360. Tests: `test_*_fits_th` in Tasks 8–13.
4. **Bug-hunt abuse:** caught > bugs, caught > cap, negative values and a second submit are all capped or refused. An event answered after the project has left PRODUCTION does not crash, and its progress effect is ignored. Tests: Task 3 (`test_caps_*`, `test_second_hunt_refused`), Task 2 (`test_answer_in_polish_ignores_progress`).
5. **Slider edits:** each stage sums to exactly 10000 after any edit, past stages are read-only, and a refused submit does not leave the UI out of sync. Tests: Task 7 (`test_rebalance_*`), Task 8 (`test_past_stage_sliders_disabled`, `test_slider_change_submits_set_sliders`).

  static func is_event_decision(content: ContentDB, d: Decision) -> bool   # content.production_events.has(d.kind)

  func _init(p_decision_id: int, p_option_index: int) -> void
